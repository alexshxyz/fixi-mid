# Документация по служебным файлам проекта

Этот документ кратко описывает файлы, которые не являются основными Python-модулями, но нужны для настройки, работы и восстановления приложения.

## `.env`

Файл с секретными настройками приложения. В текущем проекте используются:

```text
BOT_TOKEN=токен Telegram-бота
CHANNEL_ID=id Telegram-канала
```

- `BOT_TOKEN` — токен, через который приложение обращается к Telegram Bot API.
- `CHANNEL_ID` — канал или чат, куда отправляются уведомления и статистика.

Файл загружается через `python-dotenv` в `telegram_notifier.py`, `stats.py` и других модулях. Значения `.env` нельзя публиковать или добавлять в репозиторий. Файл исключён из Git через `.gitignore`.

## `bot.log`

Основной лог приложения.

В него записываются события из `main.py`, `parser.py`, `logics.py`, `storage.py` и `telegram_notifier.py`, в том числе:

- запуск и настройка браузера;
- переходы по страницам и обновление таблицы матчей;
- найденные паттерны;
- отправка Telegram-уведомлений;
- найденные дубликаты;
- ошибки парсинга, отправки и сохранения матчей;
- перезапуски страницы или приложения.

Каждая запись содержит дату и время, уровень сообщения и текст события. Файл создаётся и дополняется автоматически. Это рабочий журнал, а не постоянное хранилище данных.

Настройка логгера выполняется централизованно через [logging_config.py](../logging_config.py). Модули передают в `setup_logger()` своё имя и используют готовый объект логгера.

## `leagues.json`

Список лиг, которые считаются приоритетными для оформления уведомления.

Файл содержит объект с массивом `leagues`:

```json
{
  "leagues": [
    {
      "id": 1,
      "name": "Malta Jubilee Cup"
    }
  ]
}
```

Каждый элемент хранит:

- `id` — числовой идентификатор лиги;
- `name` — точное название лиги.

При загрузке `telegram_notifier.py` названия собираются в `leagues_list`. Если лига матча есть в этом списке, уведомление получает значок `🔥`. Для лиги, которой нет в списке, используется значок `🔒`.

## `matches.json`

Постоянное JSON-хранилище найденных и отправленных прогнозов.

Файл содержит массив записей. Одна запись имеет примерно такой вид:

```json
{
  "league": "Example League",
  "home_team": "Team A",
  "away_team": "Team B",
  "prediction": "Over 2.5 FT",
  "odds": 1.6,
  "final_score": null,
  "result": null,
  "link": "https://example.com/match/123",
  "script": null,
  "date": "2026-09-02",
  "source": "Crown"
}
```

Поля хранят:

- лигу и команды;
- текст прогноза;
- коэффициент;
- итоговый счёт и результат, если они уже известны;
- ссылку на матч;
- дату записи;
- источник коэффициентов.

Файл используется для:

- проверки дубликатов перед отправкой уведомления;
- хранения истории прогнозов;
- расчёта статистики;
- получения статистики по датам и лигам.

Если файла нет, `storage.py` создаёт его с пустым массивом `[]`. Сейчас файл существует, но пуст.

## `match_state.json`

Временный файл сохранения состояния мониторинга из `parser.py`.

Он нужен, чтобы не потерять историю при вынужденном перезапуске браузера или приложения. Файл содержит объект с тремя разделами:

```json
{
  "match_history": {
    "12345": {
      "initial": {},
      "changes": []
    }
  },
  "last_data": {
    "12345": {}
  },
  "active_match_ids": ["12345"]
}
```

- `match_history` — накопленная история изменений коэффициентов по матчам;
- `last_data` — последние извлечённые данные по матчам;
- `active_match_ids` — список активных идентификаторов матчей.

При успешной загрузке через `load_state_from_json()` состояние возвращается в `main.py`, а сам файл удаляется. Поэтому его отсутствие является нормальным состоянием, если перезапуск не выполнялся или состояние уже восстановлено.

## `requirements.txt`

Список Python-зависимостей проекта и минимальных поддерживаемых версий:

```text
playwright>=1.40.0
psycopg2-binary>=2.9.0
requests>=2.31.0
python-dotenv>=1.0.0
```

Назначение пакетов:

- `playwright` — управление браузером и получение данных с live-страницы;
- `psycopg2-binary` — PostgreSQL-драйвер, оставшийся в списке зависимостей проекта;
- `requests` — HTTP-запросы к Telegram Bot API;
- `python-dotenv` — загрузка настроек из `.env`.

Установка выполняется командой:

```bash
pip install -r requirements.txt
```

## `logging_config.py`

Общий модуль настройки логирования проекта.

Он содержит функцию `setup_logger(name, log_filename='bot.log')`, которая:

- создаёт именованный логгер с уровнем `INFO`;
- добавляет запись в файл;
- добавляет вывод в консоль;
- применяет единый формат записей.

Основные модули передают в функцию имя `__name__` и получают настроенный логгер. Для `stats.py` передаётся имя файла `stats.log`, для остальных основных модулей используется `bot.log`.

## `stats.log`

Лог фонового сервиса статистики из `stats.py`.

В файл записываются:

- запуск сервиса;
- пропуск проверки, если сегодня не первое число месяца;
- успешная отправка месячной статистики;
- ошибки расчёта статистики;
- ошибки отправки в Telegram;
- ошибки чтения или записи `stats.txt`.

Как и `bot.log`, этот файл предназначен для диагностики и не хранит статистику как структурированные данные. Сама статистика рассчитывается из `matches.json`, а отметки уже отправленных месяцев хранятся в `stats.txt`.

## Характер файлов и резервное копирование

- `.env` — секретные настройки;
- `leagues.json` — редактируемая конфигурация списка лиг;
- `matches.json` — постоянные данные прогнозов;
- `match_state.json` — временное состояние для восстановления;
- `requirements.txt` — список зависимостей;
- `logging_config.py` — единая настройка логирования;
- `bot.log` и `stats.log` — журналы работы.

Файлы `.env`, `*.log` и временные файлы состояния не должны использоваться как единственная резервная копия важных данных. Для истории прогнозов основным файлом является `matches.json`.
