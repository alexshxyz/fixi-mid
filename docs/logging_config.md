# Документация по файлу logging_config.py

## 1. Назначение файла

Файл [logging_config.py](../logging_config.py) содержит общую настройку логирования проекта.

Он устраняет дублирование конфигурации логгера в основных модулях и предоставляет единую функцию `setup_logger()`.

Модуль настраивает два направления вывода:

- файл журнала;
- консольный вывод.

Для каждой записи используется единый формат:

```text
дата и время - уровень сообщения - текст сообщения
```

Пример:

```text
2026-09-03 12:30:15,421 - INFO - Page loaded successfully
```

---

## 2. Место в работе проекта

Общий поток настройки логирования выглядит так:

```text
main.py       ─┐
parser.py     ─┤
logics.py     ─┤
storage.py    ─┼──> logging_config.setup_logger() ──> файл + консоль
stats.py      ─┘                    |
                                     └── stats.py использует stats.log
```

Основные модули используют `bot.log`:

- `main.py`;
- `parser.py`;
- `logics.py`;
- `storage.py`.

Модуль `stats.py` передаёт отдельное имя файла `stats.log`, чтобы месячная статистика не смешивалась с основным журналом приложения.

---

## 3. Функция `setup_logger(name, log_filename='bot.log')`

Создаёт и возвращает именованный объект `logging.Logger` с уровнем `INFO`.

### Параметры

#### `name`

Имя логгера. Обычно передаётся специальная переменная `__name__`:

```python
from logging_config import setup_logger

logger = setup_logger(__name__)
```

Это позволяет различать сообщения разных модулей в системе логирования Python.

#### `log_filename`

Имя файла для записи логов. По умолчанию используется `bot.log`.

Для отдельного файла статистики:

```python
logger = setup_logger(__name__, 'stats.log')
```

Путь к файлу строится относительно каталога, в котором находится `logging_config.py`.

### Возвращаемое значение

Функция возвращает настроенный объект `logging.Logger`:

```python
logger = setup_logger(__name__)
logger.info("Application started")
```

---

## 4. Настройка handler’ов

Для каждого логгера создаются два handler’а.

### `FileHandler`

Записывает сообщения в указанный файл. Для него устанавливается уровень `INFO`.

### `StreamHandler`

Выводит сообщения в консоль. Для него также устанавливается уровень `INFO`.

Оба handler’а используют форматтер:

```python
'%(asctime)s - %(levelname)s - %(message)s'
```

В результате в файл и консоль попадают сообщения одинакового уровня и формата.

---

## 5. Уровни сообщений

Так как logger и оба handler’а настроены на уровень `INFO`, выводятся сообщения следующих уровней:

- `INFO` — обычные рабочие события;
- `WARNING` — потенциальные проблемы;
- `ERROR` — ошибки;
- `CRITICAL` — критические ошибки.

Сообщения уровня `DEBUG` не выводятся.

Пример использования:

```python
logger.info("Storage initialized")
logger.warning("Table is not ready")
logger.error("Failed to save state")
```

---

## 6. Важное поведение

`setup_logger()` добавляет handler’ы при каждом вызове и не проверяет, были ли они добавлены ранее. Поэтому не следует многократно вызывать функцию для одного и того же имени логгера в рамках одного процесса: это может привести к дублированию записей.

В текущем проекте функция вызывается один раз при импорте каждого основного модуля, поэтому логирование сохраняет прежнее поведение.

Функция не создаёт отдельные каталоги для логов. Указанный файл создаётся в каталоге проекта, если у процесса есть права на запись.

---

## 7. Текущие места использования

```python
# bot.log
logger = setup_logger(__name__)
```

Такой вариант используется в `main.py`, `parser.py`, `logics.py` и `storage.py`.

```python
# stats.log
logger = setup_logger(__name__, 'stats.log')
```

Такой вариант используется в `stats.py`.
