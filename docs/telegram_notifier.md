# Документация по файлу telegram_notifier.py

## 1. Назначение файла

Файл [telegram_notifier.py](../telegram_notifier.py) отвечает за отправку уведомлений о найденных ставочных паттернах в Telegram-канал.

Он получает данные матча из [logics.py](../logics.py), формирует HTML-сообщение, проверяет, не отправлялся ли такой прогноз раньше, отправляет сообщение через Telegram Bot API и после успешной отправки сохраняет матч в [storage.py](../storage.py).

Основные задачи файла:

- загрузить настройки Telegram из переменных окружения;
- загрузить список лиг из `leagues.json`;
- сформировать ссылку на страницу матча;
- подготовить значение коэффициента;
- сформировать текст прогноза и HTML-сообщение;
- проверить дубликат перед отправкой;
- отправить уведомление в Telegram;
- сохранить успешно отправленный прогноз в `matches.json`;
- записать результат операций в `bot.log` и консоль.

Файл не ищет паттерны и не собирает данные с сайта. Поиск подходящего события выполняется в `logics.py`, а мониторинг коэффициентов — в `parser.py`.

---

## 2. Место telegram_notifier.py в работе скрипта

Общий поток данных выглядит так:

```text
parser.py
  |
  | передаёт историю изменений
  v
logics.py
  |
  | находит подходящий over/AH-паттерн
  v
telegram_notifier.py
  |
  | проверяет дубликат, отправляет сообщение
  | и сохраняет успешный прогноз
  v
storage.py
  |
  v
matches.json
```

В `logics.py` используется публичная функция:

```python
from telegram_notifier import send_telegram_notification
```

После рефакторинга её сигнатура не изменилась. Поэтому существующие вызовы для over и handicap продолжают работать без изменений.

---

## 3. Импорты и настройки

В начале файла подключаются зависимости:

- `requests` — отправка HTTP-запроса к Telegram Bot API;
- `os` — чтение переменных окружения и построение путей;
- `setup_logger` из [logging_config.py](../logging_config.py) — получение настроенного логгера;
- `json` — чтение списка лиг из JSON;
- `load_dotenv` — загрузка значений из `.env`;
- `save_match`, `check_duplicate_match` из [storage.py](../storage.py) — сохранение матча и проверка дубликата.

Все используемые внешние пакеты указаны в [requirements.txt](../requirements.txt).

### Загрузка `.env`

```python
load_dotenv(dotenv_path=os.path.join(os.path.dirname(__file__), '.env'))
```

Файл `.env` должен находиться в корне проекта рядом с `telegram_notifier.py`. Из него загружаются настройки:

```text
BOT_TOKEN=токен_бота
CHANNEL_ID=id_канала

# Необязательный SOCKS5-прокси для запросов к Telegram
TELEGRAM_PROXY_HOST=адрес_прокси
TELEGRAM_PROXY_PORT=порт_прокси
TELEGRAM_PROXY_USERNAME=логин_прокси
TELEGRAM_PROXY_PASSWORD=пароль_прокси
```

Прокси используется, только если указаны `TELEGRAM_PROXY_HOST` и `TELEGRAM_PROXY_PORT`. Логин и пароль можно оставить пустыми для прокси без авторизации. Для DNS-запросов используется схема `socks5h`.

### `BOT_TOKEN`

Токен Telegram-бота. Используется для построения URL метода `sendMessage`.

### `CHANNEL_ID`

Идентификатор канала или чата, в который отправляется уведомление.

### `TELEGRAM_API_URL`

Формируется автоматически:

```python
TELEGRAM_API_URL = f"https://api.telegram.org/bot{BOT_TOKEN}/sendMessage"
```

Если переменные окружения не заданы, URL всё равно будет создан, но реальная отправка завершится ошибкой Telegram API. При прямом запуске файла отсутствие настроек отдельно выводится в лог.

## 4. Список лиг и оформление сообщения

При импорте модуля читается файл [leagues.json](../leagues.json):

```python
leagues_file = os.path.join(os.path.dirname(__file__), 'leagues.json')
with open(leagues_file, 'r', encoding='utf-8') as f:
    leagues_data = json.load(f)
leagues_list = [item['name'] for item in leagues_data['leagues']]
```

При формировании сообщения лига сравнивается со списком `leagues_list`:

- если лига присутствует в списке, используется значок `🔥`;
- если лиги нет в списке, используется значок `🔒`.

Поэтому файл `leagues.json` должен существовать и содержать объект с массивом `leagues`, элементы которого имеют поле `name`.

---

## 5. Настройка логирования

Модуль получает логгер через общую функцию `setup_logger()` из [logging_config.py](../logging_config.py). Для `telegram_notifier.py` используется файл `bot.log`.

Настройка уровня `INFO`, файлового и консольного обработчиков выполняется только в `logging_config.py`.

В лог записываются:

- успешная отправка уведомления;
- найденный дубликат;
- ошибка HTTP-запроса;
- ошибка отправки;
- ошибка сохранения матча.

Ошибки сохранения отделены от ошибок отправки: если Telegram вернул успешный ответ, но запись в `matches.json` завершилась ошибкой, функция всё равно считает уведомление отправленным и возвращает `True`.

## 6. Внутренние функции

После разделения большая функция отправки состоит из небольших функций, каждая из которых отвечает за один этап подготовки или выполнения операции.

### 6.1. `_prepare_odds(over_odds)`

Подготавливает коэффициент для отображения в сообщении.

Функция пытается преобразовать входное значение в `float`, прибавляет `1` и округляет результат до двух знаков:

```python
_prepare_odds("0.60")  # 1.6
```

Если значение нельзя преобразовать в число, оно возвращается без изменений. Например, `None` не вызывает исключение и остаётся `None`.

### 6.2. `_build_prediction(over, handicap_text, handicap_team_order)`

Формирует строку прогноза, которая используется одновременно в сообщении и при проверке дубликатов.

Для over:

```text
Over 2.5 FT
```

Для handicap:

```text
Handicap -0.5 Home FT
```

Если `handicap_text` равен `None`, создаётся вариант over. Иначе создаётся вариант handicap с указанной стороной команды.

### 6.3. `_build_message(league, team1, team2, score, match_url, prediction, odds_value)`

Собирает итоговый текст уведомления в HTML-формате Telegram.

Сообщение содержит:

1. значок и название источника `Crown`;
2. название лиги;
3. команды и текущий счёт со ссылкой на страницу матча;
4. текст прогноза;
5. значение коэффициента.

Пример результата:

```html
<b>🔥 Crown</b>
Example League
<b><a href="https://live5.nowgoal26.com/oddscomp/1234567">Team 1 1 - 0 Team 2</a></b>
<b>Over 2.5 FT</b>
Odds 1.6
```

### 6.4. `_is_duplicate_notification(match_url, prediction, match_id)`

Проверяет, существует ли уже запись с такой же парой:

- `match_url`;
- `prediction`.

Проверка выполняется через `check_duplicate_match()` из `storage.py`.

Возвращает:

- `True`, если уведомление уже отправлялось;
- `False`, если дубликат не найден.

При найденном дубликате функция записывает сообщение в лог. В этом случае HTTP-запрос не выполняется.

### 6.5. `_send_message(payload, match_id)`

Отправляет подготовленный payload в Telegram:

```python
requests.post(
  TELEGRAM_API_URL,
  json=payload,
  proxies=TELEGRAM_PROXIES,
  timeout=10,
)
```

Результат:

- при HTTP-статусе `200` возвращается `True`;
- при другом статусе записывается текст ответа и возвращается `False`;
- при исключении запроса ошибка записывается в лог и возвращается `False`.

Таймаут запроса установлен в 10 секунд.

### 6.6. `_save_notification(league, team1, team2, prediction, odds_value, match_url)`

Сохраняет успешно отправленный прогноз через `save_match()`.

В хранилище передаются:

- лига;
- домашняя команда;
- гостевая команда;
- прогноз;
- коэффициент;
- ссылка на матч.

Ошибка записи перехватывается и логируется, чтобы она не приводила к повторной отправке уже доставленного Telegram-сообщения.

## 7. Публичная функция `send_telegram_notification(...)`

```python
def send_telegram_notification(
    league,
    team1,
    team2,
    score,
    over=None,
    over_odds=None,
    match_id=None,
    handicap_text=None,
    handicap_team_order=None,
):
```

Это единственная функция модуля, которую вызывают другие части приложения.

### Аргументы

- `league` — название лиги;
- `team1` — первая команда;
- `team2` — вторая команда;
- `score` — текущий счёт;
- `over` — значение total для over-прогноза;
- `over_odds` — исходное значение коэффициента;
- `match_id` — идентификатор матча;
- `handicap_text` — значение handicap; если не задано, используется over;
- `handicap_team_order` — сторона handicap, например `Home` или `Away`.

Аргументы `over`, `over_odds`, `match_id`, `handicap_text` и `handicap_team_order` имеют значения по умолчанию, поэтому функция поддерживает оба текущих сценария из `logics.py`.

### Последовательность работы

1. Формируется URL матча:

   ```text
   https://live5.nowgoal26.com/oddscomp/<match_id>
   ```

   Если `match_id` отсутствует, используется пустая строка.

2. Коэффициент передаётся в `_prepare_odds()`.
3. Прогноз формируется через `_build_prediction()`.
4. Сообщение собирается через `_build_message()`.
5. Создаётся payload Telegram API с `chat_id`, HTML-текстом и отключённым preview ссылки.
6. Выполняется `_is_duplicate_notification()`.
7. При дубликате функция возвращает `False` и прекращает работу.
8. Если дубликата нет, вызывается `_send_message()`.
9. При ошибке отправки функция возвращает `False` и не сохраняет матч.
10. После успешной отправки вызывается `_save_notification()`.
11. Функция возвращает `True`.

Главный порядок операций:

```text
подготовка данных
      |
      v
проверка дубликата
      |
      v
отправка в Telegram
      |
      v
сохранение в matches.json
```

Такой порядок предотвращает повторную отправку одного и того же прогноза и не сохраняет сообщения, которые Telegram не принял.

## 8. Примеры вызова

### Over-прогноз

```python
send_telegram_notification(
    league="Example League",
    team1="Team 1",
    team2="Team 2",
    score="1 - 0",
    over="2.5",
    over_odds="0.60",
    match_id="1234567",
)
```

Будет сформирован прогноз `Over 2.5 FT`, а значение коэффициента станет `1.6`.

### Handicap-прогноз

```python
send_telegram_notification(
    league="Example League",
    team1="Team 1",
    team2="Team 2",
    score="1 - 0",
    match_id="1234567",
    over_odds="0.75",
    handicap_text="-0.5",
    handicap_team_order="Home",
)
```

Будет сформирован прогноз `Handicap -0.5 Home FT`.

## 9. Прямой запуск файла

В конце файла есть блок:

```python
if __name__ == "__main__":
```

Он используется для простой ручной проверки.

Если `BOT_TOKEN` или `CHANNEL_ID` не заданы, в лог выводится предупреждение. Если настройки присутствуют, отправляется тестовое уведомление для матча с ID `1234567`.

Обычно модуль запускается не напрямую, а импортируется из `logics.py`.

---

## 10. Требования для работы

Перед запуском должны быть выполнены следующие условия:

- установлен Python 3;
- установлены зависимости из [requirements.txt](../requirements.txt);
- создан файл `.env` с `BOT_TOKEN` и `CHANNEL_ID`;
- доступен файл [leagues.json](../leagues.json);
- у процесса есть права на создание и изменение `bot.log` и `matches.json`;
- Telegram-бот добавлен в канал и имеет права на отправку сообщений.

Команда установки зависимостей:

```bash
pip install -r requirements.txt
```

При первом запуске файл `matches.json` подготавливается функциями из `storage.py`, поэтому отдельно создавать его вручную не требуется.
