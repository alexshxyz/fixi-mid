# Документация по запуску и логике файла main.py

## 1. Что делает этот файл

Файл [main.py](../main.py) является точкой входа в приложение. Он запускает основной цикл работы программы, открывает браузер, заходит на страницу спортивных live-ставок, настраивает интерфейс сайта, собирает список матчей и передаёт их в обработчик матчей (`parse_and_monitor_match`).

Основная задача этого файла — не обрабатывать данные напрямую, а подготовить окружение и запустить основной цикл мониторинга событий в браузере.

---

## 2. Какой общий сценарий работы программы

При запуске выполняется следующий порядок действий:

1. Загружаются переменные среды из `.env`.
2. Настраивается логирование в файл `bot.log` и в консоль.
3. Вызывается `init_storage()`, чтобы убедиться, что файл `matches.json` существует.
4. Запускается сервис статистики в отдельном потоке.
5. В бесконечном цикле создаётся браузер через Playwright.
6. Открывается сайт `https://live5.nowgoal26.com/`.
7. Переключается на раздел Live.
8. Выбирается компания/поставщик `Crown`.
9. Настраиваются параметры отображения odds.
10. Загружается сохранённое состояние из файла `matches.json` или собирается список матчей.
11. Запускается мониторинг матчей.
12. При необходимости скрипт перезапускается с сохранённым состоянием.

---

## 3. Импортируемые модули и их роль

В начале файла подключаются зависимости:

- `os` — работа с путями к файлам и переменными окружения.
- `sys` — работа с запуском процесса и перезапуском через `os.execv`.
- `logging` — ведение логов.
- `threading` — запуск фонового потока для статистики.
- `load_dotenv` — загрузка значений из `.env`.
- `sync_playwright` — создание и управление браузером через Playwright.
- `parse_and_monitor_match`, `load_state_from_json`, `PageRestartRequired` — логика парсинга и восстановления состояния.
- `init_storage` — создание/проверка файла `matches.json` перед началом основной работы.
- `run_stats_service` — сервис статистики, который работает параллельно.

Важный момент: этот файл подключает только запуск/настройку окружения, а не саму бизнес-логику парсинга. Сам парсинг выполняется через функции из других модулей.

---

## 4. Настройка логирования

После импортов выполняется загрузка переменных окружения:

```python
load_dotenv(dotenv_path=os.path.join(os.path.dirname(__file__), '.env'))
```

Это значит, что файл ожидает наличие файла `.env` в корне проекта. В этом файле лежат переменные BOT_TOKEN и CHANNEL_ID.

После этого создаётся логгер:

- имя логгера: `__name__`
- уровень: `INFO`
- в лог отправляются сообщения как в консоль, так и в файл `bot.log`

Логи нужны для:

- отслеживания статуса запуска;
- диагностики ошибок в браузере;
- фиксации момента перезапуска;
- контроля состояния мониторинга матчей.

## 5. Функции файла и что каждая из них делает

### 5.1. `init_storage()`

```python
def init_storage():
```

Назначение:

- убедиться, что файл `matches.json` существует;
- создать его автоматически, если его ещё нет;
- подготовить хранилище для сохранения обработанных матчей.

Что именно происходит:

- вызывается функция из [storage.py](../storage.py);
- она проверяет наличие файла и, при необходимости, создаёт пустой список `[]`.

Почему это важно:

- без этого файла дальнейшая запись данных в хранилище может завершиться ошибкой;
- запускаемый процесс должен иметь корректное storage-состояние ещё до старта основного цикла.

Обязательные условия и настройки:

- в корне проекта должна быть доступна папка для записи;
- у процесса должны быть права на создание файла `matches.json`;
- хранилище должно быть рассчитано на JSON-формат, а не на БД.

---

### 5.2. `init_browser(p)`

```python
def init_browser(p):
```

Назначение:

- создать новый браузер Chromium;
- открыть страницу в headless-режиме;
- задать размеры окна;
- перейти на сайт live-таблицы.

Что именно происходит:

- запускается `p.chromium.launch(...)`;
- включены параметры командной строки для более стабильной работы в контейнере/серверной среде;
- создаётся новая вкладка (`browser.new_page()`);
- задаётся размер окна `1280x720`;
- открывается адрес `https://live5.nowgoal26.com/`.

Почему это важно:

- без браузера невозможно взаимодействовать с сайтом;
- без правильной настройки Chromium программа не сможет найти нужные элементы интерфейса.

Обязательные условия и настройки:

- установлен Playwright и браузерные бинарники;
- сайт должен быть доступен из среды запуска;
- если селекторы на сайте изменятся, функция начнёт ломаться.

### 5.3. `close_popup(page)`

```python
def close_popup(page):
```

Назначение:

- попытаться закрыть всплывающее окно/модальное окно, которое может перекрывать интерфейс.

Что делает функция:

- пытается найти элемент `i.closebtn`;
- ждёт его появления до 10 секунд;
- кликает по нему.

Важно:

- в основном цикле эта функция сейчас не вызывается (`#close_popup(page)`), то есть всплывающие окна не закрываются автоматически в текущей версии.
- это означает, что возникновение такого окна может повлиять на работу селекторов.

Обязательные условия:

- на странице должен быть элемент с селектором `i.closebtn`;
- если его нет, функция просто пишет в лог, что окно не появилось или не закрылось.

### 5.4. `switch_to_live(page)`

```python
def switch_to_live(page):
```

Назначение:

- переключить страницу в режим Live.

Что делает:

- нажимает на элемент `li#li_FilterLive`;
- ждёт, пока появится таблица `table#table_live`.

Зачем нужно:

- сайт может иметь несколько режимов отображения матчей, и для мониторинга нужны именно live-матчи;
- без этого шага парсер может работать с неподходящими данными.

Обязательные условия:

- на странице должен присутствовать фильтр `li#li_FilterLive`;
- таблица live должна обязательно отрисовываться после клика.

### 5.5. `select_crown(page)`

```python
def select_crown(page):
```

Назначение:

- выбрать провайдера/компанию `Crown` из выпадающего списка;
- дождаться обновления таблицы данных после смены значения.

Что происходит в функции:

1. Находит `select#CompanySel`.
2. С помощью `select.select_option(value="3")` выбирает значение `3`.
3. Ожидает, пока выбранное значение действительно станет равным `3`.
4. Сохраняет текущую разметку таблицы в `previous_rows`.
5. Ждёт, пока DOM изменится: `snapshot !== prev`.
6. Если изменений не произошло, делает короткую задержку `time.sleep(1)`.

Почему это важно:

- каждая букмекерская компания/источник данных может отображать разный набор событий;
- для корректной работы нужен именно тот источник, с которым рассчитаны правила парсинга.

Обязательные условия:

- селектор `select#CompanySel` должен быть на странице;
- значение `3` должно соответствовать нужной компании на текущем сайте;
- таблица после выбора должна обновляться.

### 5.6. `configure_odds_settings(page)`

```python
def configure_odds_settings(page):
```

Назначение:

- открыть настройки отображения ставок;
- выключить один тип odds (`otc_2`);
- включить другой (`otc_3`);
- закрыть окно настроек.

Что происходит:

- нажимает `span#settingBtn`;
- ждёт появления чекбоксов `input#otc_2` и `input#otc_3`;
- устанавливает `otc_2` в `False`;
- устанавливает `otc_3` в `True`;
- закрывает настройки через `MM_showHideLayers('soccerSettingWin','','none')`.

Зачем это нужно:

- сайт может показывать несколько видов коэффициентов;
- для парсинга нужно оставить только нужный тип данных, иначе могут появляться лишние или неверные значения.

Обязательные условия:

- элементы `span#settingBtn`, `input#otc_2`, `input#otc_3` должны существовать;
- функция `MM_showHideLayers` должна быть доступна в странице;
- структура сайта должна отвечать ожидаемым селекторам.

### 5.7. `collect_matches(page)`

```python
def collect_matches(page):
```

Назначение:

- получить список ID матчей, у которых есть доступные коэффициенты.

Что происходит:

- находит все элементы, у которых `id` начинается с `time_`;
- исключает скрытые элементы (`offsetParent === null`);
- берёт ID матча из `time_...`;
- ищет ближайшую строку таблицы `tr`;
- проверяет, есть ли в ней `p.odds1` или `p.odds3`.
- если есть коэффициенты, добавляет ID в массив.

Итог:

- возвращается список матчей, которые будут обработаны дальше.

Почему это важно:

- парсер не должен обрабатывать пустые строки или матчи без odds.
- это позволяет быстро собрать только релевантные события.

Обязательные условия:

- в DOM должны быть строки с префиксом `time_`;
- нужные odds-элементы должны иметь определённые CSS-селекторы;
- сайт должен быть в режиме Live и с активным фильтром Crown.

### 5.8. `main()`

```python
def main():
```

Это главная функция запуска всего приложения.

Что она делает:

1. Вызывает `init_storage()` для проверки и создания `matches.json`.
2. Создаёт поток `stats_thread` и запускает `run_stats_service` в фоне.
3. Заходит в бесконечный цикл `while True:`.
4. Внутри каждого цикла:
   - создаёт новый Playwright-подключение;
   - запускает `init_browser(p)`;
   - переключает на Live;
   - выбирает Crown;
   - обновляет odds-настройки;
   - загружает предыдущий state через `load_state_from_json()`.
5. Если сохранённое состояние есть:
   - вызывается `parse_and_monitor_match(page, saved_state=saved_state)`.
6. Если состояния нет:
   - собираются все подходящие матчи через `collect_matches(page)`;
   - передаются в `parse_and_monitor_match(page, matches)`.
7. При возникновении `PageRestartRequired`:
   - закрывает браузер;
   - запускает тот же процесс заново через `os.execv(...)`.
8. При любой другой ошибке:
   - закрывает браузер;
   - логирует исключение;
   - пробрасывает исключение вверх, чтобы оно остановило выполнение.

Почему это главный блок:

- здесь связываются все этапы: браузер, подготовка страницы, загрузка состояния, парсинг и перезапуск.
- это точка входа, через которую происходит запуск всего приложения.

Обязательные условия:

- база данных должна быть доступна;
- сервис статистики должен запускаться без зависания;
- Playwright должен быть установлен и доступен;
- `.env` должен содержать корректные переменные окружения, если они используются;
- внешний сайт должен быть доступен и стабилен.

---

## 6. Что происходит в блоке `if __name__ == "__main__":`

```python
if __name__ == "__main__":
    main()
```

Этот блок означает:

- при прямом запуске файла Python будет вызвана функция `main()`;
- если файл импортируется как модуль, этот код не выполнится автоматически.

То есть именно этот блок делает [main.py](../main.py) исполняемым запускным файлом проекта.

## 7. Обязательные настройки для корректной работы

Ниже перечислены ключевые настройки и условия, без которых скрипт не сможет нормально работать:

### 7.1. Переменные окружения

Файл `.env` должен быть в корне проекта, потому что выполняется:

```python
load_dotenv(dotenv_path=os.path.join(os.path.dirname(__file__), '.env'))
```

Рекомендуется проверить, есть ли там необходимые секреты, токены, адреса и параметры, если проект их использует.

### 7.2. Playwright

Нужно установить пакет `playwright` и его браузеры, иначе скрипт упадёт на старте.

### 7.3. Структура DOM сайта

Большая часть кода опирается на конкретные идентификаторы HTML:

- `li#li_FilterLive`
- `table#table_live`
- `select#CompanySel`
- `span#settingBtn`
- `input#otc_2`
- `input#otc_3`
- `id` элементов вида `time_...`

Если сайт обновит разметку, эти селекторы могут перестать работать.

### 7.4. Доступ к сайту

Адрес `https://live5.nowgoal26.com/` должен быть доступен из окружения, в котором запущен скрипт.

### 7.5. Логирование

Логи пишутся в `bot.log`, поэтому каталог проекта должен быть доступен для записи.

### 7.6. Состояние матчей и статистика

`init_storage()` создаёт и проверяет файл `matches.json`, а `run_stats_service` предполагает, что сервис статистики корректно инициализирован до начала основного цикла. Данные о уже обработанных матчах читаются из файла `matches.json` через `load_state_from_json()`.

---

## 8. Краткое резюме

Файл [main.py](../main.py) выполняет роль управляющего запуска проекта:

- создаёт окружение;
- запускает фоновую статистику;
- открывает браузер;
- настраивает страницу live-таблицы;
- выбирает нужную компанию;
- собирает и отправляет матчи в обработчик;
- перезапускает процесс при необходимости.

Именно эта функция делает файл точкой входа в проект и задаёт общий сценарий работы приложения.
