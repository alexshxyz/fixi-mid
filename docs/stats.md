# Документация по файлу stats.py

## 1. Назначение файла

Файл [stats.py](../stats.py) отвечает за расчёт месячной статистики матчей и передачу готового текста в [telegram_notifier.py](../telegram_notifier.py) для отправки в Telegram-канал.

Он получает завершённые матчи из [storage.py](../storage.py), выбирает записи за прошлый календарный месяц, рассчитывает количество побед, поражений и возвратов и формирует HTML-сообщение. Отправку выполняет [telegram_notifier.py](../telegram_notifier.py).

Основные задачи файла:

- определить текущую дату по времени UTC+3;
- выбрать предыдущий календарный месяц;
- получить матчи за этот период из `matches.json`;
- рассчитать общую статистику;
- вычислить Win Rate и прибыль;
- передать готовую статистику в `telegram_notifier.py`;
- не отправлять статистику одного месяца повторно;
- работать в отдельном фоновом потоке основного приложения.

Файл не добавляет матчи и не изменяет их результаты. Записи создаются через [telegram_notifier.py](../telegram_notifier.py), а `stats.py` только читает их и формирует сводку.

---

## 2. Место stats.py в работе приложения

При запуске [main.py](../main.py) создаёт фоновый daemon-поток:

```python
stats_thread = threading.Thread(target=run_stats_service, daemon=True)
stats_thread.start()
```

Общий поток работы выглядит так:

```text
main.py
  |
  | запускает run_stats_service() в отдельном потоке
  v
stats.py
  |
  | проверяет дату и marker stats.txt
  | читает данные из matches.json
  v
storage.py
  |
  | возвращает матчи и рассчитанные значения
  v
stats.py
  |
  | передаёт итоговый текст в telegram_notifier.py
  v
telegram_notifier.py
  |
  | отправляет через настроенный прокси
  v
Telegram-канал
```

Статистический сервис работает параллельно с мониторингом live-матчей и не блокирует основной поток браузера.

## 3. Импорты и настройки

В файле используются:

- `sys` — добавление родительского каталога в `sys.path`;
- `os` — работа с путями и переменными окружения;
- `time` — ожидание между проверками сервиса;
- `setup_logger` из [logging_config.py](../logging_config.py) — получение настроенного логгера;
- `datetime`, `timedelta` — расчёт текущего и прошлого месяца;
- `send_telegram_message` из [telegram_notifier.py](../telegram_notifier.py) — передача готового текста на отправку;
- `get_matches_in_date_range`, `calculate_stats` из [storage.py](../storage.py) — чтение матчей и расчёт базовой статистики.

### Добавление пути для импорта

В начале файла выполняется:

```python
sys.path.insert(0, os.path.dirname(os.path.dirname(os.path.abspath(__file__))))
```

Это добавляет родительский каталог в начало списка путей Python. Благодаря этому модуль может импортировать `storage.py`, в том числе при запуске из другой директории.

### Переменные окружения

Настройки Telegram и прокси загружаются и используются в `telegram_notifier.py`. `stats.py` не выполняет HTTP-запросы и не содержит Telegram-конфигурацию.

### Файлы сервиса

#### `stats.log`

Файл для логов статистического сервиса. Имя файла передаётся в общую функцию `setup_logger()` из [logging_config.py](../logging_config.py). Сообщения также выводятся в консоль.

#### `stats.txt`

Файл-маркер отправленных периодов. В него добавляются строки такого вида:

```text
STATS SENT 2026-08
```

#### `matches.json`

Основное хранилище матчей. Путь к нему определяется в [storage.py](../storage.py), а `stats.py` получает данные через функции этого модуля.

## 4. Расчёт периода статистики

Сервис использует текущее время UTC+3:

```python
now_utc3 = datetime.utcnow() + timedelta(hours=3)
```

Затем определяется предыдущий календарный месяц.

Например, если текущая дата — `2026-09-02`, статистика строится за август 2026 года:

```text
начало периода: 2026-08-01
конец периода:  2026-09-01
```

Матчи выбираются вызовом:

```python
get_matches_in_date_range(first_day_last, first_day_current)
```

Границы периода работают так:

- первый день прошлого месяца включается;
- первый день текущего месяца не включается.

Отдельно обрабатывается переход с января на декабрь предыдущего года. Например, в январе 2027 года выбирается декабрь 2026 года.

Названия месяцев выводятся на английском языке заглавными буквами: `JANUARY`, `FEBRUARY`, `MARCH` и т.д.

## 5. Функция `get_last_month_stats()`

```python
def get_last_month_stats():
```

Функция получает и форматирует статистику за прошлый месяц.

### Последовательность работы

1. Получает текущую дату в UTC+3.
2. Вычисляет предыдущий месяц и год.
3. Формирует начальную и конечную даты периода.
4. Загружает матчи через `get_matches_in_date_range()`.
5. Передаёт их в `calculate_stats()`.
6. Рассчитывает Win Rate и прибыль.
7. Формирует HTML-текст для Telegram.
8. Возвращает готовую строку.

Если за период нет матчей, возвращается сообщение:

```text
📅 <b>AUGUST</b>

No data available.
```

Если возникает исключение, ошибка записывается в `stats.log`, а функция возвращает текст с ошибкой:

```text
❌ Ошибка при получении статистики: ...
```

### Формат результата при наличии данных

```text
📅 AUGUST

💰 +2.40 units 📈 70% WR

🎯 10 matches
7W / 2L / 1D
```

Название месяца и число матчей выделяются HTML-тегом `<b>`.

### Win Rate

Win Rate рассчитывается только по матчам с результатом `Won` или `Lost`:

```python
matches_without_void = wins + losses
win_rate = int(wins * 100 / matches_without_void)
```

Возвраты (`Void`) не входят в знаменатель.

Например, при результатах `7W / 2L / 1D`:

```text
WR = 7 / (7 + 2) * 100 = 77%
```

Используется целочисленное значение, поэтому дробная часть отбрасывается.

Если есть только возвраты и нет побед или поражений, `WR` равен `0%`.

### Расчёт прибыли

Прибыль рассчитывается по фиксированной модели:

- `Won` — `+0.8` units;
- `Lost` — `-1` unit;
- `Void` — `0` units.

Формула:

```text
profit = wins * 0.8 - losses
```

Например, для `7W / 2L / 1D`:

```text
profit = 7 * 0.8 - 2 = +3.60 units
```

Положительная прибыль выводится со знаком `+` и двумя знаками после запятой. Отрицательная выводится с минусом.

## 6. Передача статистики на отправку

```python
def send_telegram_message(text):
```

После расчёта `stats.py` передаёт готовый текст в `send_telegram_message(text)` из `telegram_notifier.py`. Эта функция формирует payload, выполняет запрос через настроенный SOCKS5-прокси и возвращает результат отправки.

Функция не помечает статистику как отправленную. За запись marker отвечает вызывающая функция `check_and_send_monthly_stats()`.

## 7. Защита от повторной отправки

### 7.1. `check_stats_sent(year, month)`

```python
def check_stats_sent(year, month):
```

Проверяет, есть ли в `stats.txt` строка для заданного периода:

```text
STATS SENT YYYY-MM
```

Например:

```python
check_stats_sent(2026, 8)
```

ищет строку:

```text
STATS SENT 2026-08
```

Функция возвращает:

- `False`, если `stats.txt` не существует;
- `True`, если marker найден;
- `False`, если marker не найден или файл не удалось прочитать.

Ошибка чтения не останавливает сервис: она записывается в лог, после чего возвращается `False`.

### 7.2. `mark_stats_sent(year, month)`

```python
def mark_stats_sent(year, month):
```

Добавляет в `stats.txt` строку с отправленным периодом:

```python
STATS SENT 2026-08
```

Функция вызывается только после успешного ответа Telegram. Если запись в файл не удалась, ошибка попадает в `stats.log`.

Если marker не был записан из-за ошибки, при следующей проверке сервис может попытаться отправить статистику повторно.

## 8. Функция `check_and_send_monthly_stats()`

```python
def check_and_send_monthly_stats():
```

Это основной координатор одной проверки.

### Порядок действий

1. Получает текущую дату в UTC+3.
2. Проверяет, является ли текущий день первым числом месяца.
3. Если сегодня не первое число, записывает сообщение в лог и завершает проверку.
4. Определяет прошлый месяц.
5. Проверяет marker через `check_stats_sent()`.
6. Если статистика уже отправлялась, завершает проверку.
7. Получает текст через `get_last_month_stats()`.
8. Отправляет текст через `send_telegram_message()`.
9. Если отправка успешна, вызывает `mark_stats_sent()`.

Статистика отправляется только первого числа. Даже если функция вызывается каждый день, в остальные дни отправка не выполняется.

### Защита от повторной отправки

Проверка marker происходит до формирования и отправки сообщения. После успешной отправки marker добавляется в `stats.txt`.

Логическая последовательность:

```text
сегодня 1 число?
      |
      v
marker уже есть?
      |
      v
получить статистику
      |
      v
отправить Telegram-сообщение
      |
      v
записать marker
```

## 9. Функция `run_stats_service()`

```python
def run_stats_service():
```

Запускает бесконечный цикл автоматической проверки.

Внутри цикла:

1. вызывается `check_and_send_monthly_stats()`;
2. после успешного выполнения делается пауза `86400` секунд;
3. если возникает исключение, ошибка записывается в лог и выполняется пауза `3600` секунд;
4. после обработки ошибки цикл начинается заново.

После успешной проверки следующая проверка выполняется примерно через 24 часа (`86400` секунд). При исключении следующая попытка выполняется примерно через час (`3600` секунд).

Сервис не завершается самостоятельно. Он остановится вместе с основным процессом, потому что в `main.py` запускается как daemon-поток.

---

## 10. Прямой запуск файла

В конце файла есть блок:

```python
if __name__ == "__main__":
    run_stats_service()
```

При прямом запуске:

```bash
python3 stats.py
```

сервис начинает бесконечно проверять дату и отправлять статистику по описанным правилам.

В обычном режиме файл запускается косвенно из [main.py](../main.py) в отдельном потоке.

## 11. Требования для работы

Для корректной работы должны выполняться условия:

- установлен Python 3;
- установлены зависимости из [requirements.txt](../requirements.txt);
- в `.env` указаны `BOT_TOKEN` и `CHANNEL_ID`;
- Telegram-бот имеет право отправлять сообщения в канал;
- доступен [storage.py](../storage.py);
- у процесса есть права на чтение `matches.json`;
- у процесса есть права на создание и изменение `stats.log` и `stats.txt`.

Команда установки зависимостей:

```bash
pip install -r requirements.txt
```

Файл `matches.json` создаётся и поддерживается модулем `storage.py`. Файл `stats.txt` создаётся автоматически при первой успешной отметке отправленной статистики.
