# fixi-mid — обзор проекта

`fixi-mid` — Python-бот для мониторинга футбольных матчей в Live-таблице Goaloo. Он считывает счёт, игровое время и коэффициенты, ищет заданные изменения линий, отправляет подходящие сигналы в Telegram и позже обновляет их статус.

## Как проходит обработка

1. `main.py` запускает Playwright, открывает сайт, переключается на Live и собирает ID активных матчей.
2. `observer.py` извлекает данные матчей из DOM. Также он отслеживает изменения Live-таблицы и при включённом `DEBUGMODE` записывает диагностические данные.
3. `tracker.py` управляет циклом мониторинга, историей матчей, обновлением страницы и восстановлением состояния после перезапуска.
4. `closed_ov_ah.py` анализирует историю коэффициентов рынков over и азиатской форы (AH). При совпадении с условиями передаёт сигнал в `notifier.py`.
5. `notifier.py` формирует текст сообщения, проверяет, не отправлялся ли уже этот рынок для `match_id`, отправляет сообщение в Telegram и сохраняет запись через `storage.py`.
6. `tracker.py` получает подтверждение об отправке, планирует последующее обновление статуса сообщения и сохраняет отметку в хранилище.

## Модули

| Файл | Назначение и связи |
| --- | --- |
| `main.py` | Точка входа. Настраивает Playwright и страницу, собирает активные матчи и запускает `tracker.py`. Передаёт ему функции обновления Live-таблицы и страницы. |
| `config.py` | Загружает `.env`, задаёт URL, параметры работы, Telegram-настройки и пути к данным. Также читает список лиг из `leagues.json`. |
| `observer.py` | Читает DOM Live-таблицы: статусы строк, счёт, время и котировки. Используется `main.py` и `tracker.py`. |
| `tracker.py` | Основной координатор наблюдения: хранит историю и последние данные матчей, реагирует на изменения таблицы, запускает анализ и обрабатывает отложенное обновление Telegram-сообщений. Использует `observer.py`, `closed_ov_ah.py`, `notifier.py` и `storage.py`. |
| `closed_ov_ah.py` | Ищет сигналы по закрытию рынков over и AH и подтверждающим коэффициентам. При совпадении вызывает `notifier.py`. |
| `notifier.py` | Нормализует и отображает линии и игровое время, формирует HTML-сообщение, отправляет его через Telegram Bot API и передаёт запись в `storage.py`. |
| `storage.py` | Читает и записывает `matches.json`, проверяет отправленные рынки по `match_id`, обновляет отметки уведомлений и рассчитывает статистику. |
| `logger.py` | Настраивает именованные логгеры с выводом в консоль и файл; основной файл логов — `bot.log`. |

## Конфигурация и данные

- `.env` содержит секреты и настройки окружения, например `BOT_TOKEN`, `CHANNEL_ID` и параметры Telegram-прокси. Не добавляйте этот файл в Git и не публикуйте его содержимое.
- `leagues.json` — список лиг, используемый `tracker.py` при выборе отметки для отправленного сообщения.
- `matches.json` — основное хранилище уведомлений и результатов; путь можно переопределить переменной `MATCHES_FILE`.
- `match_state.json` — временное состояние мониторинга для восстановления после перезапуска; после загрузки состояние читается и файл удаляется.
- При `DEBUGMODE = 1` создаются диагностические `count.json` и `data_closed_ov_ah.json`.
- `matches.csv` — экспорт матчей из `matches.json`, создаваемый утилитой `tools/export.py`.
- `bot.log` и `monitor.log` — журналы основного процесса и мониторинга лог-файла. Эти runtime-файлы не являются исходным кодом.

## Утилиты и тесты

- `tools/export.py` экспортирует записи из `matches.json` в CSV.
- `tools/stats_manual.py` содержит ручные функции расчёта и форматирования статистики по матчам и лигам.
- `tools/monitor.py` периодически проверяет свежесть последней записи `bot.log` и отправляет статус в Telegram.
- `tests/` содержит pytest-тесты модулей. Smoke-тесты, требующие реального браузера или внешних сервисов, помечены `smoke` и по умолчанию исключены настройками `pytest.ini`.

## Запуск и эксплуатационные особенности

- Основной процесс запускается командой `python main.py`; для зависимостей предусмотрены `requirements.txt` и `requirements-dev.txt`.
- Для работы нужны доступ к сайту и действительные параметры Telegram в окружении.
- `main.py` запускает браузер через локальный SOCKS5-прокси `127.0.0.1:10808`. Это отдельная настройка от Telegram-прокси, задаваемого в конфигурации.
- Код организован плоскими Python-модулями в корне проекта; импорты между ними используют имена этих модулей.
